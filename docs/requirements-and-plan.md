# Анализ требований и план разработки TaskFlow

## 1. Требования
### Функциональные:
- Регистрация и вход пользователей (JWT).
- CRUD операции для задач (создание, чтение, обновление статуса, удаление).
- Управление тегами и привязка их к задачам (связь M:M).
- Фильтрация задач по статусу и тегам, пагинация.

### Нефункциональные:
- Безопасность: защита от SQL-инъекций, XSS, IDOR (BOLA).
- Производительность: время ответа < 2с, индексы БД для частых выборок.
- Ограничения: монолит на Node.js + SQLite, релиз MVP к концу семестра.

## 2. План разработки
1. Анализ требований и проектирование БД (ER-модель).
2. Настройка каркаса Express и подключение SQLite.
3. Реализация модуля аутентификации (JWT, bcrypt).
4. Разработка REST API для задач и тегов.
5. Интеграционное тестирование и настройка CI/CD.

## 3. Реестр рисков
| Риск | Последствие | Мера |
|---|---|---|
| Требования «плывут» | Срыв сроков MVP | Заморозка спецификации OpenAPI |
| Утечка паролей | Компрометация пользователей | Хеширование bcrypt (cost=10) |
| SQL-инъекции | Утечка/удаление БД | Prepared statements (better-sqlite3) |
| Доступ к чужим данным (IDOR) | Нарушение конфиденциальности | Проверка `user_id` в каждом SQL-запросе |
