# ADR-001: Сохранение TaskFlow в виде модульного монолита

- Статус: принято для текущего MVP
- Дата: 2026-10-31

## Контекст

TaskFlow — учебный продукт с личными задачами и тегами. Текущий стек: Node.js 22, Express, SQLite, статический интерфейс. Нагрузка и состав команды невелики; отдельные домены, независимые релизные циклы и необходимость горизонтального масштабирования отдельных функций пока не подтверждены измерениями. SQLite упрощает локальный запуск, но предполагает постоянное хранилище и ограничивает параллельную запись.

## Рассмотренные альтернативы

| Модель | Скорость старта | Эксплуатационные затраты | Масштабирование | Риск для текущего MVP |
|---|---|---|---|---|
| Монолит | Высокая | Низкие | Масштабируется целиком | Смешение модулей по мере роста |
| Модульный монолит | Высокая | Низкие/умеренные | Сначала масштабируется целиком; границы модулей облегчают выделение сервисов | Требует дисциплины зависимостей |
| Микросервисы | Ниже на старте | Высокие: сервисы, сеть, наблюдаемость, CI/CD, распределённые транзакции | Независимое масштабирование компонентов | Избыточная сложность и распределённая согласованность |
| Serverless | Быстрый для отдельных функций | Зависит от числа вызовов и платформы | Функции масштабируются автоматически | Текущая файловая SQLite и состояние приложения не подходят модели без локального состояния |

## Решение

Сохранить единый развёртываемый процесс Node.js, но разделить ответственность по модулям: маршруты (HTTP-контроллеры), сервисы (правила и транзакции), слой данных и middleware. Все операции с SQLite выполняются внутри приложения; клиент обращается только к REST API.

## Последствия

**Положительные:** простое локальное развертывание; единые транзакции и схема; меньше инфраструктурных компонентов; сервисы можно тестировать независимо от HTTP-маршрутов.

**Ограничения и риски:** один процесс и одна БД остаются общей точкой отказа; SQLite ограничивает интенсивную конкурентную запись; масштабирование путём запуска нескольких процессов требует отдельной стратегии для БД и сессий.

## Условия пересмотра

ADR пересматривается, если появятся подтверждённые замеры высокой конкурентной записи, независимые команды/домены, требования отдельного масштабирования функций или SLA, которые невозможно обеспечить текущей схемой.
