# Каталог бизнес-правил TaskFlow

| ID | Правило | Приоритет | Сущности | Реализация | Проверка |
|---|---|---|---|---|---|
| BR-01 | Email пользователя уникален и нормализуется к нижнему регистру | Высокий | users | UNIQUE(email), `auth-service` | Повторная регистрация возвращает 409 |
| BR-02 | Пароль при регистрации должен содержать не менее 8 символов; хранится только bcrypt-хеш | Высокий | users | Zod, bcryptjs | Валидация и сценарии регистрации/входа |
| BR-03 | Название задачи содержит от 1 до 200 символов | Высокий | tasks | Zod + CHECK | Тест пустого и слишком длинного title |
| BR-04 | Статус задачи может быть только `active` или `completed` | Высокий | tasks | Zod + CHECK | Тест допустимых и недопустимых статусов |
| BR-05 | Дедлайн не может предшествовать времени создания задачи | Высокий | tasks | Проверка в сервисе + CHECK | Тест прошлого дедлайна |
| BR-06 | Пользователь может читать и изменять только собственные задачи | Критический | users, tasks | JWT middleware и `WHERE user_id = ?` в сервисе | IDOR/BOLA-тест: другой пользователь получает 404 |
| BR-07 | Пользователь может управлять только собственными тегами | Критический | users, tags | `WHERE user_id = ?` | Попытка удалить/использовать чужой тег |
| BR-08 | Один пользователь не может создать два тега с одинаковым именем | Средний | tags | UNIQUE(name, user_id) | Повторное создание возвращает 409 |
| BR-09 | К задаче назначаются только теги её владельца; повторяющиеся ID не дублируются | Высокий | tasks, tags, task_tags | Проверка принадлежности и уникализация tagIds | Создание задачи с чужим tagId возвращает 400 |
| BR-10 | Полная замена набора тегов выполняется атомарно | Высокий | task_tags | Транзакция `replaceTaskTagSet` | Проверка замены набора; ошибка не оставляет частичные связи |
| BR-11 | При переходе в completed фиксируется completed_at; при возврате в active он очищается | Средний | tasks | `task-service` | Тест обоих переходов |
| BR-12 | Удаление задачи или тега удаляет зависимые строки task_tags | Средний | tasks, tags, task_tags | FK ON DELETE CASCADE | Проверка каскада в тесте БД |
| BR-13 | События создания/изменения/удаления задач и тегов записываются в аудит | Средний | audit_logs | `writeAuditLog` вызывается сервисом | Тест наличия audit event после операции |
| BR-14 | Ошибки API имеют единую JSON-структуру | Высокий | API | `errorHandler` | Интеграционные тесты кодов 400/401/404/409 |
| BR-15 | Секреты и хеши паролей не передаются в ответах и не хранятся в Git | Критический | users, config | DTO публичного пользователя, .gitignore, env | Проверка ответа и состава файлов репозитория |
| BR-16 | Частота API-запросов и попыток аутентификации ограничивается | Средний | API | Rate limiter middleware | Проверка заголовков лимита; лимит не применяется в тестовом окружении |

## Сервисные границы

- `auth-service`: регистрация, проверка пароля, выпуск JWT и получение публичного профиля.
- `task-service`: правила задач, проверка владельца, работа с тегами, транзакции и аудит.
- `tag-service`: создание, чтение и удаление тегов владельца, аудит операций.
- `routes`: HTTP-валидация, вызов сервиса и формирование ответа; SQL и бизнес-операции в маршрутах не размещаются.
