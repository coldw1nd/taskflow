# План тестирования БД, бизнес-правил и API

## Наборы проверок

| Уровень | Что проверяется | Реализация |
|---|---|---|
| БД | integrity_check, внешние ключи, ограничения CHECK/UNIQUE, каскадное удаление, индексы и миграции | `tests/database.test.js`, `npm run db:check` |
| Интеграция API | Регистрация/вход, CRUD задач, теги, валидация, статус-коды, изоляция пользователей | `tests/api.test.js` (исходная база — 21 сценарий; добавлены проверки журнала аудита) |
| Бизнес-правила | Проверка владельца, дедлайнов, статусов, тегов, уникальности и аудита | `src/services/`, тесты API и БД |
| Контракт | Сверка путей и моделей со спецификацией OpenAPI и проверка ответов Supertest | `openapi.yaml`, `/api/docs`, интеграционные тесты |
| Производительность | Сравнение времени ответа GET списка задач при limit=10 и limit=100; вывод средней, медианы и P95; план SQL | `scripts/perf.mjs`, `npm run db:check` |

## Команды

```bash
npm run lint
npm test
npm run db:check
npm run perf
```

Скрипт `scripts/perf.mjs` регистрирует тестового пользователя и создаёт тестовые задачи в БД экземпляра API, к которому он подключён. Поэтому замер следует выполнять на отдельной временной БД, а не на основной пользовательской базе.

В первом окне PowerShell из корня проекта задайте отдельный файл БД и порт, затем примените миграции и запустите сервер:

```powershell
$env:DB_FILE = "taskflow-perf.sqlite"
$env:PORT = "3100"
npm run migrate
npm run dev
```

Во втором окне PowerShell выполните замер:

```powershell
$env:BASE_URL = "http://localhost:3100"
$env:TASK_COUNT = "100"
$env:RUNS = "20"
npm run perf
```

После сохранения результатов остановите тестовый сервер (`Ctrl+C`) и удалите временные файлы базы из корня проекта:

```powershell
Remove-Item taskflow-perf.sqlite* -ErrorAction SilentlyContinue
```

Число тестовых задач и повторов можно уменьшить через переменные `TASK_COUNT` и `RUNS`. В `.gitignore` добавлено правило для всех файлов `*.sqlite` и их WAL/SHM-файлов.

## Применение и откат миграций

Миграции применяются автоматически при запуске приложения или командой `npm run migrate`. Откат выполняется в обратном порядке. Сначала остановите приложение и вручную скопируйте файл SQLite в безопасное место, затем выполните:

```bash
npm run db:rollback -- 003_query_indexes.sql
npm run db:rollback -- 002_audit_log.sql
```

Миграция `001_core.sql` является базовой и её откат удаляет бизнес-таблицы. Он разрешается только после ручного копирования файла SQLite и явного подтверждения:

```bash
CONFIRM_DESTRUCTIVE_ROLLBACK=yes npm run db:rollback -- 001_core.sql
```

Для существующей рабочей БД откат базовой схемы выполнять не требуется. Перед любым откатом обязательно сохраните отдельную копию файла SQLite вручную.
